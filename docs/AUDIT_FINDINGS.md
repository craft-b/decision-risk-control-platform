# Enterprise Asset Intelligence — Audit Findings (Stage 1, static review)

**Scope:** full read of `shared/`, `ml-service/`, `server/`, infra/config, targeted client review.
**Date:** 2026-07-07 · **Reviewer stance:** everything in README/metadata treated as a claim to verify.
**Verification status:** all findings below are confirmed *statically* (by reading code). Items marked
**[S2]** need a targeted execution check in Stage 2 to quantify impact.

---

## Context: what this codebase actually is

The repo is substantially more mature than a typical demo: three calibrated multi-horizon RF models
(v1.14), a real temporal holdout + `TimeSeriesSplit` CV, a data-quality gate, three-layer drift
detection, a champion/challenger registry with shadow scoring, MLflow hooks, 115 Python tests + Node
unit tests in CI, and a working dispatch risk guard in the UI. The audit below is therefore not
"demo lacks rigor" — it is "the rigor claimed in the README is undermined by five specific defects
in the feature/label pipeline and by how metrics are surfaced."

All data is **simulated** (10 seeded units + fleet renewal, weekly snapshots 2024–2032 ≈ 22k rows).
The README discloses the simulation but reports the resulting metrics as headline performance.

| ML-1 | **P0** | Temporal leakage | [feature-engineering-enhanced.ts:176-261](../server/services/feature-engineering-enhanced.ts) | Rental, maintenance, last-maintenance and MTBF queries have **no upper time bound** (`>= d90` but never `<= snapshotTs`). Backfilled snapshots (seed-orchestrator.ts:182, routes.ts:1304-1341 both route here) therefore read events that happen **after** the snapshot date. `maintenance_cost_180d` (#2 feature by importance) can include the very MAJOR_SERVICE event that becomes the label; `days_since_last_maintenance` and `mean_time_between_failures` (both top-5 features) are computed with future knowledge; a future event even clamps `daysSince` to 0 via `Math.max(0,…)`. ## Top structural risks — narrative

**1. The headline metrics don't survive their own pipeline (ML-1 + ML-3 + ML-2).**
The README's evaluation story (temporal holdout, TimeSeriesSplit, gap=horizon) is genuinely the
right design — but it's built on feature vectors that were backfilled with unbounded queries, so
the "past-only" property the whole story depends on is false at the source. Even with ML-1 fixed,
the holdout has no embargo and no asset grouping, and even with *that* fixed, the labels are the
simulator's own threshold rules over the model's own features. The correct diligence posture:
current AUCs verify the pipeline plumbing, not predictive power. The product needs (a) the leak
fixes, (b) honest re-evaluation, and (c) an explicit "synthetic-data metrics" framing until real
fleet data exists.

**2. Probabilities shown to users are not calibrated probabilities (ML-5 + ML-8 + ML-9).**
Calibration is a named feature ("calibrated Random Forest"), but SMOTE-before-calibration inflates
every probability; thresholds 0.30/0.60, the dispatch guard, the cost model's break-even math, and
the projection curve all consume those inflated numbers — and the projector additionally feeds the
model mis-scaled features. The dashboard then mislabels ROC-AUC as precision. Every number a fleet
manager sees passes through at least one of these defects.

**3. The model-governance story has a hole exactly where it claims safety (ML-7 + SEC-1).**
Champion/challenger + shadow scoring is the repo's most enterprise-credible pattern, but version
pinning doesn't pin preprocessing artifacts, and the unauthenticated FastAPI port lets anyone
promote a model without the Node-layer admin checks. The pattern is right; the enforcement isn't.

**4. Cross-service contract is convention, not contract (ARCH-1 + ML-10 + ML-6).**
Three implementations of the feature definitions (TS enhanced service, Python training SQL +
transforms, Python projector aging), two DB access layers doing DDL independently, and imputation
defaults that differ by code path. Every future feature change has four places to forget.

**5. First-run experience is broken by a one-line bug (OPS-1).**
`trainAndPoll` polls a field that doesn't exist; the demo seed — the exact flow an investor or
interviewer runs — should always report failure at the training step. Worth fixing before anything
else is shown to anyone.

## What's genuinely good (keep and say so)

- Right evaluation *architecture* (temporal holdout + TSCV + gap), right label censoring at
  cursor−60d, and honest in-code commentary about distribution shift.
- Data-quality gate blocking training, three-layer drift detection persisted to DB, agent API with
  machine-readable `recommended_action`, monitor loop with auto-retrain triggers.
- Champion/challenger with shadow scoring and zero-downtime promotion (fix ML-7 and it's real).
- Dispatch risk guard with mandatory HIGH-risk acknowledgement — a real decision-support loop.
- `eventSource` taxonomy on maintenance events — the exact hook needed to fix the label problem.
- CI runs lint + typecheck + both test suites on every push.
